1. Overview & Threat Landscape

Manual footprinting does not scale. A mature adversary facing a thousand-person organisation cannot afford to click through LinkedIn profiles one by one or run dig by hand. Automation transforms reconnaissance from a cottage craft into an industrial pipeline: seed a domain, enrich it across passive and active sources, correlate entities in a graph, and export a targeting package ready for phishing, vulnerability scanning, or physical impersonation.

Modern threat actors (ransomware affiliates, APT groups, and initial-access brokers) operate recon-as-a-service.

They use:

  • Automated subdomain enumeration to discover forgotten admin panels, dev APIs, and staging environments.
  • Metadata extractors to pull usernames, internal hostnames, and printer paths from every PDF and Word document indexed by Google.
  • Graph-link tools to map the shortest path from a target domain to a personal Gmail or GitHub account.
  • AI-driven correlation engines to summarise terabytes of news, commits, and leaked dumps into human-readable targeting briefs.

This module treats automation not as a convenience but as a force multiplier. Every command you script today is tomorrow's adversary playbook.
Defenders must understand the speed and scale of automated recon to build detection and deception strategies that keep pace.

BlueOps Note:
If your attack surface can be mapped in twenty minutes by a Python script and a free API key, so can your competitor's and your adversary's. The question is not whether automation works, but whether your monitoring notices when it happens.

2. Adversarial Methodology: Automated Recon Pipeline

  1. Phase 1: Seed & Scope Ingestion
    • Ingest a root domain, executive name list, or ASN.
    • Validate scope boundaries (subdomain depth, IP range limits, out-of-scope TLDs).
  2. Phase 2: Passive Enrichment at Scale
    • Harvest subdomains, certificates, and DNS records without touching the target directly.
    • Query archive services (Wayback, Common Crawl) for historic endpoints and leaked documents.
    • Scrape people-data from LinkedIn, job boards, and conference speaker lists.
  3. Phase 3: Metadata & Document Extraction
    • Download public documents (PDFs, DOCs, PPTs) and extract EXIF, embedded paths, author names, and software versions.
    • Parse GitHub repositories for secrets, internal URLs, and dependency trees.
  4. Phase 4: Correlation & Graph Analysis
    • Load entities (domains, emails, IPs, usernames) into link-analysis platforms.
    • Identify weak links: personal emails reused as admin contacts, overlapping name servers, shared GitHub contributors.
  5. Phase 5: AI-Assisted Summarisation & Target Prioritisation
    • Use NLP to classify documents, summarise news sentiment, and flag executive mentions.
    • Generate Google dorks and search queries automatically based on discovered technology stack.
  6. Phase 6: Weaponisation Prep
    • Export target packages (email lists, technology stacks, credential-spraying dictionaries) to phishing frameworks or Cobalt Strike.
    • Schedule recurring monitoring for new subdomains, job postings, or leaked credentials.

4. Traditional & Hybrid Footprinting Tools

4.1 Maltego: Graph-Based Relationship Mapping

Maltego maps relationships between people, organisations, domains, and infrastructure. Use pre-defined entities to expand a target domain into linked email addresses, phone numbers, domains, and footprinting artefacts. Capture graph exports for reporting. 

# Maltego Classic / XL workflow (GUI):
1. New Graph -> Entity: Domain [iscsecurity.org]
2. Right-click -> Run Transform: "DNS from Domain" (using Paterva or local transforms)
3. Results populate:
   - NS: ns1.cloudprovider.com, ns2.cloudprovider.com
   - MX: mail.protection.outlook.com (indicates Microsoft 365)
   - A: 203.0.113.45
4. Run Transform: "Emails from Domain [theHarvester]"
   - alice@iscsecurity.org -> Entity: Email
   - bob@iscsecurity.org -> Entity: Email
5. Pivot Email -> "To Person [Pipl]" or "Social Network Links [Sherlock]"
   - alice@iscsecurity.org -> LinkedIn: Alice Johnson
   - bob@iscsecurity.org -> GitHub: bobcodes

6. Export graph as PDF/SVG: maltego_iscsecurity_graph_2025-11-11.pdf

Graph reveals: Two employees with personal GitHub presence;
GitHub commit history exposes dependency on legacy-logging library.

4.3 subfinder: Passive Subdomain Enumeration

Passive subdomain enumeration using multiple online sources. Supports JSON and file outputs. It collects subdomains passively using multiple online OSINT sources, ideal for building a clean list of candidate hosts without triggering active scans. 

# Example: enumerate subdomains silently and save results to domains.txt
$ subfinder -d iscsecurity.org -silent -o domains.txt

$ cat domains.txt

staging.iscsecurity.org
mail.iscsecurity.org

old.iscsecurity.org
Adversarial Analysis:
staging, dev, and old subdomains are high-value targets, often less hardened than production. vpn and api suggest direct ingress points.
Feed these into httpx or nmap for service discovery.

4.4 Recon-Dog & BillCipher: Multi-Purpose Recon Wrappers

Recon-Dog and BillCipher are multi-purpose reconnaissance wrappers that call public APIs, perform DNS/Whois lookups, detect CMS fingerprints, and aggregate results into a single output. They are useful for rapid initial enumeration in controlled lab exercises.

7. Create & Run a Custom Footprinting Script

Orchestration scripts tie together disparate tools into a single reproducible pipeline. The example below performs basic automated footprinting on a safe demo domain (iscsecurity.org), a domain owned and controlled for training purposes. All queries are directed at infrastructure that has been explicitly authorised for demonstration use.

7.1 Example Python Script

#!/usr/bin/env python3
import subprocess

def dns_lookup(domain):
    return subprocess.getoutput(f"dig {domain} ANY +noall +answer")

def whois_lookup(domain):
    return subprocess.getoutput(f"whois {domain}")

def email_enumeration(domain):
    # Save XML output and limit results to 100 (adjust as needed)
    return subprocess.getoutput(f"theHarvester -d {domain} -b all -l 100 -f isc_harvest.xml")

def run_footprinting(domain):
    print("Performing DNS Lookup...")
    print(dns_lookup(domain))

    print("\nPerforming Whois Lookup...")
    print(whois_lookup(domain))

    print("\nEnumerating Emails...")
    print(email_enumeration(domain))

if __name__ == '__main__':
    run_footprinting("iscsecurity.org")

8. AI Considerations & OPSEC

  • Prompt Engineering Discipline: Be explicit in prompts when asking AI to generate scripts. Supply expected inputs, outputs, and allowed tools.
    A vague prompt may generate brute-force code that exceeds scope.
  • Data Exposure: Avoid exposing client data or secrets to third-party AI services unless contractually authorised and privacy controls are in place. Assume prompts are logged and may be used for model training.
  • Model Provenance: Record model name/version and prompt used for reproducibility. If a finding is later challenged, you must prove the chain of
    AI-assisted inference.
  • False Positives: AI summarisation can hallucinate entities (e.g., inventing a vendor relationship). Always validate AI-extracted hostnames and emails against primary sources.
  • Rate Limiting & Proxy Rotation: Automated scripts and AI scrapers can trigger IP bans, WAF blocks, and legal flags. Implement exponential back-off, rotate user-agents, and respect robots.txt where feasible.
  • Credential Hygiene: Never embed API keys (Maltego, Shodan, Hunter.io) directly in scripts. Use environment variables or secret managers.
    A leaked key in a public repo becomes an immediate supply-chain risk.

9. Case Studies

Case Study 1: The 0ktapus Campaign (2022): Automated Recon at Telecom Scale

The 0ktapus threat actor (also linked to the Twilio and Cloudflare breaches) systematically targeted telecommunications and technology companies using automated OSINT pipelines. They scraped LinkedIn and corporate websites with scripted tools to harvest thousands of employee phone numbers and email addresses. Using this dataset, they launched mass SMS-phishing campaigns directing victims to fake Okta login portals. The initial recon was entirely automated: username enumeration, phone-number correlation, and lookalike-domain registration were executed via commodity tooling and templates.
The campaign succeeded because the adversary treated reconnaissance as a bulk-data operation rather than a manual effort.

Automated people-recon enables mass spear-phishing. Blue teams must monitor for bulk enumeration of employee contact data and implement out-of-band verification for any credential-reset request initiated via SMS.

Case Study 2: WormGPT & FraudGPT (2023–2024): AI Automation of Social Engineering

Cybercriminal forums began advertising "WormGPT" and "FraudGPT" AI models trained or fine-tuned for malicious purposes. These tools automated the generation of phishing emails in multiple languages, reverse-engineered obfuscated code, and summarised large document dumps to extract PII.
In documented incidents, attackers used AI to parse thousands of leaked résumés from recruitment databases, identifying candidates who listed internal system credentials (e.g., "Experience with CrowdStrike, Okta, and AWS IAM") and then generated customised vishing scripts. The AI reduced the recon-to-weaponisation cycle from days to hours.

AI summarisation and generation lower the skill barrier for reconnaissance. Defenders must assume that every public document, résumé, and repository commit is being ingested by adversarial AI and turned into targeting intelligence.

Case Study 3: Exposed Metadata Leading to Ransomware Initial Access (2021)

A mid-sized healthcare provider suffered a ransomware breach traced to an initial access broker (IAB). The broker had used automated document-harvesting tools (functionally equivalent to FOCA combined with Google dorks) to locate publicly archived PDF invoices. The metadata revealed the internal hostname \\MEDFILE01\Finance, the software version of the electronic medical record (EMR) system, and the Windows username of the finance director. Using this intelligence, the IAB crafted a convincing fake software-update email referencing the exact EMR version. The resulting macro-enabled document executed Cobalt Strike, leading to full domain compromise.

Note:
Metadata in public documents is not "hidden", it is machine-readable attack surface. Organisations must strip metadata before publishing and monitor archive sites for document removal.

10. OPSEC & Legal Boundaries

10.1 Operational Security

  • API Key Compartmentalisation: Run Maltego, Shodan, and Hunter.io keys inside isolated VMs. Never store keys in plain-text scripts committed to GitHub.
  • Proxy & Rotation Hygiene: Bulk subdomain enumeration and Google dorking trigger rate limits. Use reputable proxy pools or cloud functions distributed across regions.
  • Source Integrity: Download Recon-Dog, BillCipher, and DarkGPT wrappers from verified repositories. Supply-chain attacks have poisoned OSINT tools with credential-stealing backdoors.
  • Archive Scraping Caution: The Wayback Machine and Common Crawl are invaluable but may cache content the target has since removed.
    Verify current state before reporting a finding as "live."
  • AI Data Residency: If the engagement is subject to GDPR, HIPAA, or ITAR, do not upload client documents to US-cloud-hosted AI services without data-processing agreements.

10.2 Legal Boundaries

Framework Constraint Risk
CFAA/CMA Automated scraping that violates a website's Terms of Service (ToS) may constitute unauthorised access. Criminal prosecution; civil injunction.
GDPR/Data Protection Automated aggregation and AI processing of employee PII (emails, names, phone numbers) require lawful basis and data-handling safeguards. Regulatory fines up to 4% global turnover.
Copyright & Database Rights Bulk downloading of documents from archive sites may infringe copyright or database rights. Civil liability; takedown orders.
Computer Fraud & Abuse (International) Querying foreign Regional Internet Registries (RIR's), search engines, or social platforms from an unauthorised vantage point may implicate local anti-hacking statutes. Extradition risk; asset seizure.
RoE/Engagement Contract Automated tools can recurse beyond scope (e.g., subfinder discovering a partner's subdomain). Hard-code scope limits and validate outputs before further action. Contract breach; loss of accreditation.
Golden Rule (ROE):
If you are not certain the activity is within signed Rules of Engagement (RoE) and legal review, do not execute it. When in doubt, use only passive, unauthenticated techniques.

11. Quick Triaging Checklist: Automated Footprinting Workflow

□ Scope Confirmation
    □ Domain/IP boundaries defined and hard-coded in scripts.
    □ Rate limits and proxy usage approved.
    □ API keys provisioned with read-only, scoped permissions.

□ Phase 1 — Passive Enumeration
    □ Run subfinder (or amass) with -silent and -o for baseline subdomain list.
    □ Query certificate transparency logs (crt.sh, Censys) for additional hosts.
    □ Check archive.org and Common Crawl for historic endpoints.

□ Phase 2 — Document & Metadata Harvesting
    □ Identify public PDF/DOC/XLS files via Google dorks or DorkGPT suggestions.
    □ Download samples and run FOCA / ExifTool for metadata extraction.
    □ Extract usernames, hostnames, software versions, and internal IPs.
    □ Review GitHub repos with OSS Insight or manual dorking for secrets.

□ Phase 3 — Relationship Mapping
    □ Import entities (domains, emails, usernames) into Maltego.
    □ Run transforms for DNS, social network, and breach correlations.
    □ Export graph and identify shortest-path attack chains.

□ Phase 4 — AI-Assisted Analysis
    □ Configure Taranis AI alerts for executive and technology mentions.
    □ Use ChatPDF to parse large documents for hidden infrastructure details.
    □ Generate additional Google dorks via DorkGPT based on stack identified.
    □ Validate all AI-generated findings against primary sources.

□ Phase 5 — Continuous Monitoring
    □ Set up Bardeen.ai or cron jobs to re-run subdomain enumeration weekly.
    □ Monitor Google Alerts / Mention for brand + breach keywords.
    □ Dark-web monitoring (authorised only) for credential leaks referencing target domain.

□ Phase 6 — Evidence & Reporting
    □ Save raw tool outputs (XML, JSON, CSV) with ISO 8601 timestamps.
    □ Store scripts and AI prompts in version control for reproducibility.
    □ Redact API keys and sensitive metadata from shared report annexes.
    □ Append defensive recommendations: subdomain monitoring, metadata scrubbing, secret scanning.

13. Defensive Countermeasures & Threat Mapping

13.1 Blue Team Mitigations

  • Subdomain Monitoring: Continuously monitor certificate transparency logs and DNS registrations for new subdomains. Alert on unexpected dev, staging, or api entries.
  • Metadata Sanitisation: Implement a document-scrubbing gateway that strips author names, internal paths, and revision history from all PDFs and Office files before publication.
  • Deception Subdomains: Plant honeypot subdomains (e.g., admin.target.com) that trigger alerts when scanned by tools like subfinder or amass.
  • Secret Scanning: Use TruffleHog, GitHub Advanced Security, or GitLab Secret Detection to block commits containing API keys, AWS tokens, or database passwords.
  • Rate Limiting & Bot Detection: Implement CAPTCHA and IP-based rate limiting on public-facing directories to slow automated scrapers and dorking.
  • Archive Removal: Regularly request removal of outdated documents from the Wayback Machine and search-engine caches to reduce historical exposure.
  • AI-Generated Content Detection: Deploy email filters that flag messages with linguistic patterns consistent with AI-generated phishing (overly formal, generic salutations) and enforce external-sender banners.
  • API Key Governance: Rotate keys quarterly; use scoped read-only permissions; monitor for anomalous query volumes from a single key.

14. Ethical Considerations & Engagement Scope

  • Scope Enforcement in Automation: Automated scripts recurse and correlate at machine speed. Hard-code domain/IP allow lists and validate every output against the Rules of Engagement before further probing.
  • Respect for Rate Limits: Aggressive scanning burdens target infrastructure and shared services (archive.org, search engines). Implement polite delays and respect robots.txt guidelines.
  • AI Accountability: When AI generates a targeting list or exploit script, the human operator remains responsible for its execution. Never delegate "go/no-go" decisions to an AI model.
  • Data Minimisation: Automated tools collect indiscriminately. Filter outputs to retain only intelligence relevant to the engagement. Securely purge unrelated personal data and PII.
  • Third-Party AI Services: Uploading a client's confidential documents to ChatPDF or Taranis AI may constitute a data breach under GDPR or contractual confidentiality terms. Use on-premise or contracted AI instances where required.
  • Responsible Disclosure: When automation discovers exposed credentials or internal hostnames, report them immediately. Do not use them for unauthorised lateral movement "just because they were easy to find."
