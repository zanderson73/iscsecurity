Google Dorking Cheatsheet

1. Basic FTP Directory Discovery

inurl:ftp intitle:"index of"
Note:
Find open FTP directory listings indexed by search engines. These often contain unlisted files and archives.

2. Specific Filetype Discovery

Examples:

inurl:ftp intitle:"index of" filetype:pdf
inurl:ftp intitle:"index of" filetype:xls
inurl:ftp intitle:"index of" filetype:doc
inurl:ftp intitle:"index of" filetype:zip|rar
Operator Note:
Locate manuals, reports, spreadsheets, and compressed backups. Always confirm scope before downloading.

3. Sensitive Information Discovery

inurl:ftp intitle:"index of" intext:password
inurl:ftp intitle:"index of" intext:confidential
inurl:ftp intitle:"index of" intext:backup
Note:
These queries can reveal exposed credentials or backups. Treat any discovered secrets per your rules of engagement.

4. Media & Data Types

inurl:ftp intitle:"index of" (mp3|wav|flac)
inurl:ftp intitle:"index of" (jpg|png|gif|raw)
inurl:ftp intitle:"index of" filetype:csv|txt

5. Excluding & Refining Results

inurl:ftp intitle:"index of" -inurl:(http|https)
inurl:ftp intitle:"index of" -site:example.com
Operator Note:
Use exclusions to avoid HTTP mirrors or domains outside your target scope.

6. Combine for Smart OSINT Targets

inurl:ftp intitle:"index of" intext:"2019" filetype:pdf
inurl:ftp intitle:"index of" intext:salary filetype:xls
inurl:ftp intitle:"index of" filetype:config
Note:
Narrow queries by year, product, department, or keyword to reduce noise and surface relevant leaks.

7. Advanced / Compound Usage

inurl:ftp intitle:"index of" ext:(doc|pdf|xls|txt|ps|rtf|odt|sxw|psw|ppt|pps|xml)
Operator Note:
Use ext: or filetype: to target multiple extensions in a single pass.

8. Usage Tips

  • Always tailor intext: keywords to what you seek (software, licenses, email, passwords, keys).
  • filetype: and ext: are interchangeable for extension targeting.
  • Combine with site: for institution-specific searches: inurl:ftp intitle:"index of" site:.edu "exam results".
  • Use numeric/keyword filters to narrow to year, project name, or department.
Note:
Document every dork you run. Search results change quickly and must be reproducible for reporting and retests.

9. Updates & Current Notes (2026)

  • NAPALM/SearchFTPS: Remains an active, widely used FTP indexer. Useful for rapid discovery and bulk download of publicly available FTP artifacts.
  • Mamont (MMNT): Is still available and commonly referenced as a large open FTP index/mirror. Use mirrored endpoints (when available) to improve coverage.
  • Metagoofil: Remains part of Kali toolsets and community forks; it helps harvest metadata and document paths found via search. Check the Kali package page or GitHub for the latest install and usage notes.
  • Community-maintained lists, Reddit threads, and Medium writeups are still good signals for finding active mirrors and lesser-known catalogs — treat them as leads, not authoritative sources.
Operator Note:
Tool availability and index freshness change; validate any critical lead directly on the indexer and record retrieval timestamps for reporting.

Supporting Resources & Recommended Reading

  • RFC 959: File Transfer Protocol (FTP) Path: Official FTP protocol specification; reference for commands, server behavior, and response codes.
  • OWASP WSTG: File & Directory Enumeration Path: Testing guidance for directory indexing, exposed files, and recursive discovery methods.
  • SearchFTPs/NAPALM FTP Index Path: Public FTP index for discovering open FTP directories and file listings.
  • Mamont (MMNT) FTP Index Path: Long-standing FTP indexing engine useful for historical and mirrored directory listings.
  • Metagoofil: Metadata Extraction Tool Path: Extract usernames, paths, software versions, and metadata from documents found via FTP dorks.
  • Shodan: Public FTP Services Path: Identify open FTP services, anonymous login configurations, and exposed directory structures.
  • Internet Archive: Wayback Machine Path: Locate historical FTP pages, cached directory indexes, and removed files.
  • CISA: Traffic Light Protocol (TLP) Path: Guidelines for handling and sharing sensitive data discovered during OSINT operations.

Why This Matters:
Google Dorking remains one of the most effective passive reconnaissance techniques. By mastering these queries, operators can uncover forgotten infrastructure, exposed documents, and configuration files that would otherwise remain hidden. For defenders, understanding these dorks is essential for proactive exposure monitoring and de-indexing sensitive content before adversaries discover it.

11. Key Takeaways

Concept Why It Matters Security Impact
Dorks Are Passive Reconnaissance Google Dorks allow discovery of exposed content without directly interacting with the target's infrastructure. Enables low-risk enumeration of sensitive files and forgotten endpoints.
Filetype Targeting Is Precise Using filetype: or ext: narrows results to specific document types, reducing false positives. Accelerates discovery of leaks, configuration files, and backups.
Combine Operators for Precision Layering site:, inurl:, intitle:, and intext: creates highly targeted queries. Reduces noise and improves intelligence quality.
Exclusions Prevent Scope Creep Using - and -site: removes unwanted domains and results from the query. Keeps engagement data clean and relevant.
Document Everything Search results change quickly; reproducible queries are essential for reporting and retests. Auditability supports legal defensibility and peer review.
Index Freshness Varies Google, Bing, Yandex, and specialized FTP indexes have different retention and refresh rates. Cross-referencing multiple engines reduces blind spots.
Metadata Extraction Adds Value Documents discovered via dorks can be analyzed with tools like Metagoofil to extract usernames and paths. Provides additional intelligence for phishing and infrastructure mapping.
Legal Boundaries Are Critical Dorking is passive reconnaissance — until it crosses into accessing unauthorized systems or data. Always operate within signed rules of engagement and document authorization.
RedOps Reminder: Dorks are sensors — tune them carefully, document everything, and never exceed your authorization. The difference between discovery and intrusion is permission; keep your queries auditable and your findings ethical.
